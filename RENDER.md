# Deploying SynapseJudge to Render

A free deployment: one Render web service, one free Key Value (Redis) instance,
and a free MongoDB Atlas cluster. No credit card, no server to administer.

**Read this first — the tradeoff.** Render does not expose a Docker daemon to
your container, so the sandbox this project is built around cannot run there.
On Render, submissions are executed by a hosted [Judge0](https://judge0.com)
instance instead (`EXECUTION_PROVIDER=judge0`).

| | Docker provider (a VM) | Judge0 provider (Render) |
| --- | --- | --- |
| Who isolates the code | This project | Judge0 |
| Network egress blocked | `--network none`, verified | Judge0's policy |
| Read-only rootfs, cap-drop, PID/memory ceilings | Yes, verified | Not ours to guarantee |
| Untrusted source leaves your infrastructure | No | **Yes — sent to a third party** |
| Judging works offline | Yes | No |

If the containerised sandbox is the point of the project, deploy to a VM with
[DEPLOY.md](DEPLOY.md) instead. Use this path when you want it online for free
and judging just needs to work.

---

## 1. MongoDB Atlas (free, 5 min)

Render has no managed MongoDB, so the database lives at Atlas.

1. Sign up at [mongodb.com/cloud/atlas](https://www.mongodb.com/cloud/atlas)
2. **Create** → **M0** (free forever, 512 MB) → pick a region near you
3. **Database Access** → Add user, remember the password
4. **Network Access** → Add IP → **Allow access from anywhere** (`0.0.0.0/0`)
   Render's free tier has no static outbound IP, so this cannot be narrowed.
   The database is still password-protected.
5. **Connect** → **Drivers** → copy the connection string

Append the database name before the `?`:

```
mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/synapsejudge?retryWrites=true&w=majority
```

If the password contains `@ : / ?` or `#`, percent-encode it or the URI will not parse.

## 2. Deploy the blueprint

1. Push this repository to GitHub
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**
3. Select the repo. Render reads [`render.yaml`](render.yaml) and proposes a web
   service plus a Key Value instance.
4. Fill in the two prompted values:

| Variable | Value |
| --- | --- |
| `MONGO_URI` | the Atlas string from step 1 |
| `SEED_ADMIN_PASSWORD` | **a password you choose** |

**Set `SEED_ADMIN_PASSWORD`.** Without it the admin account is created with the
password published in this repository's README, on a site anyone can reach.

5. **Apply**. First build takes 3–5 minutes.

Everything else — `JWT_SECRET`, `REDIS_URL`, the origin — is wired by the
blueprint. `JWT_SECRET` is generated by Render and never touches the repo.

## 3. First run

Your site is at `https://synapsejudge-XXXX.onrender.com` (Render shows the URL).

On first boot the service seeds itself: 7 problems, 3 arenas, and two accounts.
`SEED_ON_BOOT` is idempotent, so redeploys will not duplicate anything — but
once you are live you can set it to `false` in the dashboard to save a few
seconds per deploy.

| Handle | Password |
| --- | --- |
| `admin` | whatever you set as `SEED_ADMIN_PASSWORD` |
| `demo` | `demo12345` |

Check `https://your-url.onrender.com/api/health` — it should return
`{"ok":true,...}`.

## What you are running

```
Render web service (free, 512 MB)
  ├── Express API
  ├── client/dist  (SERVE_CLIENT=true — no separate static service)
  └── judge worker (RUN_WORKER_IN_API=true)
        │
        ├── Render Key Value  ── BullMQ queue
        ├── MongoDB Atlas     ── data
        └── ce.judge0.com     ── code execution
```

The API/worker split that [`ecosystem.config.cjs`](ecosystem.config.cjs) uses on a
VM is collapsed into one process here, because Render's free tier has no
background-worker type. That is only reasonable because judging is an outbound
HTTP call on this provider rather than local CPU work.

## Free-tier limits worth knowing

- **The service sleeps after 15 minutes of inactivity.** The next request takes
  ~30 seconds to wake it. Reviewers will hit this. A paid instance ($7/mo)
  removes it.
- **Judge0's public instance is rate limited** and offers no uptime guarantee.
  For anything real, self-host Judge0 or set `JUDGE0_URL` to your own instance,
  with `JUDGE0_API_KEY` if it requires one.
- **Atlas M0 is 512 MB** — thousands of submissions, not millions.
- **512 MB of RAM** on the web service. Fine, since no containers run locally.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Build fails on `sh: 1: vite: not found` | `NODE_ENV=production` makes npm skip devDependencies, and vite is one | Build command must be `npm install --include=dev && npm run build`. A plain `npm install` is not enough once `NODE_ENV=production` is set. |
| `MongoServerError: bad auth` | password wrong or not URL-encoded | Re-copy from Atlas; percent-encode `@ : / ? #` |
| Connections time out to Atlas | IP allowlist | Atlas → Network Access → `0.0.0.0/0` |
| Every submission is `internal_error` | Judge0 unreachable or throttled | Check `JUDGE0_URL`; the public instance rate limits |
| Site loads, API 404s | `SERVE_CLIENT` unset | Must be `"true"` |
| Submissions stay `pending` | worker not running | `RUN_WORKER_IN_API` must be `"true"`; check `REDIS_URL` is wired |
| First request takes 30s | free tier cold start | Expected; upgrade to remove |

## Moving to a real sandbox later

Nothing here is a one-way door. On a VM with Docker, drop
`EXECUTION_PROVIDER`, `RUN_WORKER_IN_API` and `JUDGE0_URL`, and the project goes
back to running every submission in its own locked-down container. The judging
interface is identical; only the provider changes. See [DEPLOY.md](DEPLOY.md).
